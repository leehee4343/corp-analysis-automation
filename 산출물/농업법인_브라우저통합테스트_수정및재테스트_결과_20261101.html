2. 결함 수정 및 재테스트

D001 — 숫자 범위 최소값/최대값 역전

구분내용
원인기업목록 및 업종별 목록의 공통 검색 폼에 최소값 ≤ 최대값 검증이 없었고, API도 역전 범위를 그대로 수용하였다. 레거시 매출 범위 필터는 결측값을 0으로 간주하고 최대값을 배타적으로 비교하는 불일치도 있었다.
수정네 가지 지표(매출액, 영업이익, 당기순이익, 부채비율)에 공통 범위 검증을 추가했다. 화면은 요청 전에 검색을 차단하고 인라인 오류 및 aria-invalid를 표시한다. API는 비정상 범위와 비유한 숫자를 HTTP 422로 거부한다. 빈값, 0, 음수, 단일 경계 및 동일 경계는 유효하게 유지했다.
재테스트기업목록 1,000~0 입력 시 네트워크 요청 수 6→6, 업종별 영업이익 1,000~0 입력 시 3→3으로 요청이 발생하지 않았다. 0~0으로 정정하면 요청이 정상 발생했다. 직접 API 호출도 역전 범위 422, 동일 0 범위 200, 음수 영업이익 범위 200을 확인했다.
판정PASS

D002 — 영업관리 화면의 소형 화면 가로 넘침

구분내용
원인270px 사이드바가 문서 흐름 안에서 본문 폭을 차지하고 헤더·선택 상자·범위 입력에 고정 폭이 적용되어 소형 화면에서 전체 페이지 폭을 밀어냈다.
수정1,100px 이하에서 사이드바를 본문 폭과 독립된 오버레이로 전환하고 기본 접힘 상태를 적용했다. 헤더·카드·버튼·필터를 유동형으로 바꾸고, 데이터 표의 넓은 열은 페이지가 아니라 표 컨테이너 내부에서 스크롤되도록 유지했다.
재테스트390×844, 768×1024, 1024×768, 1366×768, 1920×1080 해상도에서 접힘/펼침 동작과 문서 폭을 측정했다. 모든 해상도에서 페이지 가로 넘침이 없었으며 데스크톱 사이드바 동작도 유지됐다.

  • frontend/index.html — 인라인 검증, 접근성 속성, 반응형 레이아웃 및 사이드바 동작

  • tests/test_frontend_contract.py — 화면 검증 및 반응형 계약 테스트

6. 테스트 제약 및 후속 확인

  • 연결형 브라우저 제어 호스트를 사용할 수 없어 실제 Microsoft Edge를 헤드리스 CDP 방식으로 실행했다.
  • 모바일 항목은 실제 단말이 아닌 브라우저 뷰포트 기반 테스트다.
  • 기존 운영 데이터 및 PDF는 변경·삭제하지 않았고, 자동 테스트는 임시 SQLite 데이터베이스에서 수행했다.
  • 다운로드는 브라우저 저장 완료 UI 대신 HTTP 응답과 실제 파일 바이트를 검증했다.
